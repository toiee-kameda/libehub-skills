# ump（Upgrade My Prompt）

## このスキルの目的

初心者のざっくりした依頼を、本人への質問を通じて具体化し、「そのまま使えるプロンプト」に仕上げる。

ゴールは2つ。

1. 今回の依頼がうまくいくプロンプトを作る
2. 次回、本人が最初から少し良いプロンプトを書けるようになる

## 起動

ユーザーが `/ump` と入力したときだけ起動する。自動起動はしない。
`/ump` の前後にある文章を「元の依頼」として扱う。元の依頼がなければ、何をしたいかを一言で聞く。

## 大原則：埋めるのではなく、聞く

足りない情報を Claude が勝手に補って成果物を作らない。元の依頼の作業（Webページを作る、など）にはまだ着手しない。
代わりに質問で本人の意図を引き出す。本人の答えが、プロンプトの中身になる。

ただし、文脈から明らかなことや、答えによって結果がほとんど変わらないことは聞かない。質問は少ないほど良い。

## 何を聞くか（判断基準）

元の依頼を読み、次の観点のうち「答えによって成果物が大きく変わるのに、まだ分からないもの」を選んで聞く。

- 目的：何のために使うか、誰に向けたものか
- 成果物の形：形式、分量、含めたい要素
- 品質の基準：トーン、雰囲気、参考にしたいもの
- 制約：避けたいこと、使えないもの、環境や期限
- 素材：本人が持っていて、渡すべき情報

「いい感じ」「わかりやすく」「おしゃれに」のような曖昧な言葉は、その中身を選択肢にして聞く絶好のポイントである。

## 質問の出し方

- 1回にまとめて最大4問。追加の質問は原則1往復まで。
- 各質問に3〜4個の具体的な選択肢をつけ、自由記述も受け付ける。
- 選択肢は、初心者が「あ、これだ」と選べる日常の言葉にする。専門用語を使うなら短く補足する。
- 選択肢を表示できるツール（AskUserQuestion など）があれば使う。なければ番号付きリストで示し、「番号でも自由記述でもOK」と添える。
- 「おまかせ」の選択肢を入れてよい。おまかせされた項目は、プロンプト内で Claude に判断を委ねる書き方にする。

## プロンプトの生成

回答をもとに、元の依頼をアップグレードしたプロンプトを作る。

- コピーしやすいようにコードブロックに入れる。
- 本人の言葉と回答を活かす。回答にない前提を Claude が足さない。
- 構成の目安は「何をしてほしいか → 目的・背景 → 成果物の条件 → 避けたいこと・制約」。短い依頼なら見出しはいらない。
- 長くしすぎない。本人が読んで「これは自分の依頼だ」と分かる長さにする。

## アドバイス（学びのパート）

プロンプトのあとに、短いアドバイスを添える。

- 元の依頼とアップグレード版の差のうち、効果が大きいもの1〜2点を取り上げ、なぜ効くのかを一言で説明する。
- 「次からは最初に◯◯を一言足すだけで、質問が減ります」のように、次回すぐ使える形にする。
- 元の依頼に良い点があれば具体的に1つ伝える。欠点を無理に作らない。
- 講義や網羅的な解説はしない。全体で3〜4行程度にする。

## 最後に

次の選択肢を示す。

1. このプロンプトで実行する
2. 一部を直す
3. コピーして自分で使う

「実行する」が選ばれたら、そのプロンプトを依頼として作業に入る。

## 流れのイメージ

元の依頼：「いい感じのWebページを作って /ump」

質問の例：

- 何のページ？ → 自分のお店・教室の紹介 / イベントの告知 / 自己紹介・ポートフォリオ / その他（自由記述）
- 「いい感じ」とは？ → シンプルで落ち着いた / 明るくポップ / 高級感・上品 / おまかせ
- 見た人に最後にしてほしいことは？ → 問い合わせ / 申し込み・予約 / 読んで知ってもらうだけ / その他
- 入れたい情報で、すでに手元にあるものは？ → 自由記述（文章、写真、連絡先など）

アドバイスの例：

> 今回いちばん効いたのは「誰に、何をしてほしいページか」です。これが分かると、Claude は見出しやボタンの文言まで目的に合わせられます。次からは「◯◯向けの、△△してもらうためのページ」と一言足してみてください。
