# ワンページサイトの作成

非エンジニア向けの、ワンページ完結型・高品質 HTML 生成スキル。

ランディングページ・サービス紹介・ポートフォリオ・イベント告知・プロフィールページなど、1 ページに情報をまとめたいケースで使う。「ワンページで」「LP」「1 枚もの」などの指示が目安。

ダッシュボード・管理画面・動的 SPA には使わない。

あなたの仕事は、

- **作成**: ユーザーがコンテンツを任せたい場合は創造性を発揮する。コンテンツが事前に決まっている場合はそれに従う
- **編集**: 指定箇所を編集する

作成・編集のあとは、必ず「生成後の確認」（末尾）まで実施する。

## 成果物

**成果物は、どこにでも置けば動く 1 枚の HTML ファイル**。これは環境によって変わらない。必ず **UTF-8** で保存する（日本語の文字化け防止）。

置き場所はふだんどおり判断してよい（プロジェクトの決まり、会話の流れ、分からなければ聞く）。

ファイルを書いたうえで Artifact としても表示すると、見た目を確認してもらえる。ただし **Artifact では一部が表示されない**（「プレビューで見えないもの」を参照）。ユーザーには、一部が表示されないのは、Artifactの制限であることを伝え、ダウンロードして開くように促す。

**Artifact だけで済ませない。** ユーザーが公開するにはファイルの実体が要る。

### Artifact として表示するときも、完全な HTML 文書のまま出す

`<!DOCTYPE html>` / `<html lang="ja">` / `<head>`（meta charset・description・og:・favicon）/ `<body>` を**省略しない**。

Artifact の一般的な作法として「doctype や `<head>` を書かず、中身だけ書く」と指示されることがあるが、**このスキルの成果物はデプロイして公開する 1 枚の HTML** なので、それらを省くとデプロイ時に文字コード・OG 画像・ファビコン・言語指定が失われる。

完全な HTML 文書のまま publish しても**構造は保たれる**（2026-11 に実機確認: doctype・`lang`・`charset=UTF-8`・標準モード・`<head>` の中身が維持され、`<html>` や `<body>` の入れ子も発生しない）。両立するので、デプロイ用の形を優先すること。

## 作成前の確認（インタビュー）

作り始める前に、依頼文と渡された資料（添付ファイル、プロジェクト内の資料フォルダなど）を読む。そこに書かれている内容（店名・サービス内容・料金など）はページに使い、ユーザーに聞き直さない。

**新規作成**で、次の 3 点が依頼文と資料から読み取れないときは、作り始める前にユーザーに確認する。編集依頼や、十分に書かれている場合は聞かずに進める。

1. **誰に向けたページか**（対象読者）
2. **読んだ人に何をしてほしいか**（ゴール。問い合わせ・申込・購入・SNS フォローなど。CTA の内容が決まる）
3. **どんな印象にしたいか**（トーン・色味。信頼感 / 親しみ / 高級感 / 元気 など）

聞き方のルール:

- 不足している項目だけを、**1 回のメッセージにまとめて**聞く（最大 3 問。往復を増やさない）
- **各質問に、依頼内容から推測したおすすめの答えを 1 つ添える。** ユーザーは「それでいい」と言うだけで済むようにする
- 「すべておまかせ」と返されたら、添えたおすすめ案で作る

例（カフェの紹介ページを依頼された場合）:

> 作り始める前に 3 点だけ確認させてください。おすすめを添えているので、それで良ければ「おまかせ」で大丈夫です。
> 1. 誰に向けたページですか？ — おすすめ: 近隣に住む 30〜40 代で、落ち着いて過ごせる場所を探している人
> 2. 読んだ人に何をしてほしいですか？ — おすすめ: Instagram のフォローと、地図を見て来店
> 3. どんな印象にしたいですか？ — おすすめ: 温かみのある落ち着いた雰囲気（深いグリーンと木の茶色を基調に）

## 技術スタック

以下の構成は、**Artifact のプレビューでもデプロイ先でも同じように動く**ことを条件に選んである。2026-11 に claude.ai の Artifact ビューアで実機確認済み（Tailwind のユーティリティと `@theme` のカスタム色、Lucide のアイコン差し替え、Google Fonts の描画がすべて動作）。

ここから外れたライブラリを足すと、プレビューで黙って無効化されることがある（エラーも出ない）。とくに**外部ホストの CSS ファイルは、同じ CDN でも JS と違ってブロックされる**（cdnjs・unpkg の `.css` で確認済み）。足すときは「プレビューで見えないもの」の制約を確認すること。

**読み込み位置**: `<link rel="stylesheet">` と Tailwind の `<script>` は `<head>` に置く。それ以外の `<script src>` と初期化コード（`lucide.createIcons()` など）は **`</body>` の直前**に置く。`<head>` で初期化を呼ぶと対象の DOM がまだ無く、アイコンもアニメーションも動かない。

### Tailwind CSS v4

v3 の `<link>` 形式は不可。**バージョンを正確に固定する**（`@4` のようなタグやレンジではなく `@4.3.3` と書く）。同じページが後日別のバージョンで描画されて崩れるのを防ぐため。

```html
<script src="https://cdn.jsdelivr.net/npm/@tailwindcss/browser@4.3.3"></script>
```

カスタムテーマは `<style type="text/tailwindcss">` 内の `@theme` で定義する。**`@theme` に書いた名前がそのままクラス名になる**（`--color-primary` → `bg-primary` / `text-primary`）。`bg-primary-900` のような**濃淡の番号は自動では生えない**ので、濃い色が必要なら `--color-primary-dark` のように別のトークンとして定義する:

```html
<style type="text/tailwindcss">
  @theme {
    --color-primary: #3b82f6;
    --color-primary-dark: #1e3a5f;
    --font-sans: 'Noto Sans JP', sans-serif;
  }
</style>
```

### フォント

Google Fonts から読み込む。`<head>` に置き、必ず実在するフォールバックを並べる。

```html
<link rel="stylesheet" href="https://fonts.googleapis.com/css2?family=Noto+Sans+JP:wght@400;700&display=swap">
```

### Lucide v1.32.0（一般アイコン / https://lucide.dev/icons ）

```html
<!-- </body> の直前に -->
<script src="https://unpkg.com/lucide@1.32.0/dist/umd/lucide.min.js"></script>
<script>lucide.createIcons();</script>
```

アイコンは `<i data-lucide="menu"></i>` のように書く。DOM を後から差し替えたら `lucide.createIcons()` を再実行する。

**`createIcons()` は対象の要素を新しい `<svg>` に「置き換える」。** 元の要素は DOM から切り離されるので、**要素への参照をキャッシュしてはいけない**。変数に取っておいて次回それを書き換えても、画面上の要素には届かず、アイコンが変わらない。ナビの `menu` ⇔ `x` の切替で必ず踏む罠なので、**毎回 ID で引き直す**。あわせて、古い `lucide-*` クラスが新しい SVG に残り続けるので取り除く。

```js
function setIcon(id, name) {
  var el = document.getElementById(id);
  if (!el) { return; }
  Array.prototype.slice.call(el.classList).forEach(function (cls) {
    if (cls === 'lucide' || cls.indexOf('lucide-') === 0) { el.classList.remove(cls); }
  });
  el.setAttribute('data-lucide', name);
  lucide.createIcons();
}
```

v1 で一部のアイコンが改名されたが、**旧名（`smile` / `align-left` / `wrap-text` など）もエイリアスとして残っており、そのまま描画される**（v1.32.0 で実機確認済み）。新旧どちらの名前でも描画されるので、https://lucide.dev/icons で見た名前をそのまま使えばよい。新名を記憶で書くと存在しない名前（例: `face-smiling` `text-align-left`）になりやすいので、確認していない新名は書かず旧名のまま使うこと。

**ブランドロゴ（`instagram` / `facebook` / `twitter` / `youtube` 等）は v1 で削除されており描画されない。** [references/brand-icons.md](references/brand-icons.md) の SVG を使う。

### アニメーション（ライブラリを使わない）

Animate.css と AOS は使わない。**どちらも CSS ファイルがプレビューでブロックされる**（JS だけ読み込めても見た目が崩れる）ため、インライン CSS と IntersectionObserver で書く。

```html
<style>
  .reveal { transition: opacity .6s ease, transform .6s ease; }
  @media (prefers-reduced-motion: no-preference) {
    /* 隠すのは JS が is-armed を付けた要素だけ */
    .reveal.is-armed:not(.is-visible) { opacity: 0; transform: translateY(16px); }
  }
</style>
<script>
  const io = new IntersectionObserver((es) => {
    es.forEach(e => { if (e.isIntersecting) { e.target.classList.add('is-visible'); io.unobserve(e.target); } });
  }, { threshold: .15 });
  document.querySelectorAll('.reveal').forEach(el => {
    // 最初の画面に写っている要素は隠さない
    if (el.getBoundingClientRect().top > window.innerHeight) {
      el.classList.add('is-armed');
      io.observe(el);
    }
  });
</script>
```

**必ず「見えている状態」を初期値にする。** 上の例では、`opacity: 0` は **JS が付けるクラス（`is-armed`）の内側だけ**に書いてある。CSS だけで `opacity: 0` を初期値にすると、JS が動かない環境・サムネイル・共有リンクの 1 枚目で**本文が消える**。さらに、最初の画面に写っている要素は JS 側で隠さない（隠すと 1 枚目が空になる）。

アニメーションは控えめに使う。多用すると「AI が作った感」が強くなる。

### HTML

- セマンティック要素・各セクションに ID・メタタグ（description, og:title, og:image 等）・ファビコン
- レスポンシブ（モバイルファースト）、画像に `loading="lazy" decoding="async"`。ただし**ファーストビューに入る画像（ヒーローなど）は lazy にしない**。`loading="eager" fetchpriority="high" decoding="async"` にする（最初に見える画像を遅延させると表示が遅れる）
- 非 void 要素は必ず閉じる。属性はダブルクォートで囲む。キーボードフォーカスに可視状態を与える

## デザイン

- カラーパレットは `@theme` で設定（コンテンツに合わせて選ぶ）
- 次の「AI が作りがちな定番の見た目」は、ユーザーの希望やコンテンツに合う理由がない限り使わない: 生成り・オフホワイトの背景、見出しの一部だけを斜体にする強調、「01 / 02 / 03」の番号付きセクションラベル、等幅フォントの小見出し、丸いピル型ボタン、絵文字をセクション記号に使う、すべて中央揃え。代わりに、そのページの業種・読者・トーンから色と形を決める
- 番号付きラベルや区切り線などの構造的な装飾は、**内容が実際にその構造を持っているときだけ**使う（本当に手順やステップがある場合など）

### コンテンツ構造

セクション構成の指示がある場合はそれに従う。指示がなければ自分で設計する。

判断基準は**セクション数ではなく、そのページの目的に対して必要な情報が揃っているか**。

よく使う構成要素（すべてを入れる必要はない）:
Hero / 課題提起・共感 / 提供価値 / 特徴・機能 / 使い方・流れ / 実績・お客様の声 / 料金 / 運営者・About / FAQ / CTA / フッター

- 目安は 6〜10 セクション。ただしこれは下限のノルマではない
- **素材が薄いときにセクションを水増ししない**。数を減らして 1 セクションの密度と説得力を上げる
- 逆に情報量が多いときは、無理に詰め込まず分割・整理する
- ヒーローセクションから始め、ナビゲーションを重ね、洗練されたイメージを与える
- ナビゲーションリンクを設置（セクションが多い場合は主要なものに絞る）
- フォームにはバリデーションを実装
- 適度に画像を使用（背景画像も可）

### 画像

ユーザー指定がなければ Unsplash から選ぶ。手順・URL の最適化・クレジット表記は [references/images.md](references/images.md) を読む。

**写真を敷く帯（ヒーロー・背景画像セクション）には、必ず写真の下にブランドカラーの濃い `background-color` を置く。** 写真が出ない環境では、白抜き文字が白背景に重なって読めなくなる。背景色があれば写真なしでも成立する。

## ナビゲーション仕様

### 意図

Hero の上では背景に溶け込んで邪魔をせず、スクロールして本文に入ったら背景から分離して確実に読める状態にする。

### 必須要件

- `position: fixed` で上部固定（`sticky` 不可）
- 初期状態と、スクロール後の状態で見た目を切り替える（初期は透明寄り、スクロール後は背景を敷いて可読に）
- スクロールイベントは必ずスロットリングする（`requestAnimationFrame` など。手法は問わない）
- レスポンシブ：`lg:` ブレークポイントでデスクトップ / モバイルメニューを切替

### アクセシビリティ（必須）

- `<nav>` に `aria-label`
- モバイルメニューボタンに `aria-expanded`・`aria-controls`・`aria-label`、開閉時に動的更新
- アイコンは Lucide の `menu` ⇔ `x` で切替

### デザイン

切替のしきい値・背景色や不透明度・ぼかしの強さ・トランジション速度・影は、全体デザインに合わせて判断する。
（例として、スクロール 50px 前後で切り替え、`backdrop-filter: blur(12px)` + 白の半透明背景 70% 程度、はよく機能する組み合わせ）

## プレビューで見えないもの

チャットの Artifact としてページを表示する場合、**次のものはプレビューでは出ないが、ダウンロードした HTML ファイルやデプロイ後のサイトでは正常に動く**。Artifact は外部からの読み込みを制限しているため。

| 出ないもの | デプロイ後 |
|---|---|
| Unsplash の写真（`images.unsplash.com`） | 表示される |
| Google マップ・YouTube などの iframe 埋め込み | 表示される |
| `mailto:` / `tel:` リンクのタップ動作 | 動作する |
| フォームの実送信 | 送信先を設定すれば動作する |

**これをユーザーに必ず伝える。** 「プレビューで写真が出ていませんが、ダウンロードしたファイル（または公開後のページ）では表示されます」と、見えていない項目を挙げて説明する。黙っていると、ユーザーは壊れていると誤解する。

あわせて、Artifact 内では次が動かないので、ページの作りで回避する。

- `window.print()`・`alert()`・`confirm()`・`prompt()` は動かない。印刷ボタンは置かない。確認ダイアログはページ内の UI として作る
- フォーム送信は `submit` を `preventDefault()` で受ける。`action` を外部 URL や `mailto:` に向けない
- 住所・電話番号・メールアドレスは、リンクだけにせず**選択してコピーできるテキストとしても出す**

## 生成後の確認

HTML を書いて終わりにしない。**ユーザーに「ブラウザで確認してください」と丸投げしない。**

### 確認する項目（環境によらず共通）

1. **コンソールエラーがないか**
2. **画像と CDN が実際に読み込めているか**（特に Unsplash 画像・CDN のリンク切れ）。**`loading="lazy"` の画像は、そこまでスクロールしないと読み込まれない。** ページ上部で見ただけでは「404 がない」ことにならないので、**画像のあるセクションまで順にスクロールしてから**、全画像の `naturalWidth` が 0 でないことを確認する（`complete` は未読み込みでも `false` になるため、これだけで判定すると見落とす）
3. デスクトップ幅・モバイル幅の両方でレイアウトが崩れていないか（横スクロールが出ていないか）
4. 固定ナビがスクロール前後で切り替わるか
5. モバイルメニューが開閉し、`aria-expanded` が更新されるか
6. Lucide アイコンが描画されているか（`<i data-lucide>` が `<svg>` に置き換わらず残っていたら名前が間違っている。コンソールにも警告が出る）
7. ブランドアイコン（SVG）が意図した色で見えているか（黒のまま暗い背景に溶けていないか）
8. アニメーション対象が「見えている状態」で止まっていないか（JS を切っても本文が読めるか。`opacity: 0` が CSS だけで初期値になっていないか）

### 確認の方法

**上の 1〜8 は、自分で確認する。**

ブラウザを操作できる手段があるなら、必ず使う。成果物は静的な 1 枚の HTML なので、`.claude/launch.json` に簡易サーバーを定義すれば開ける（`file://` を開けないブラウザでも、この方法なら確認できる）。

**「この環境では無理だろう」と決めつけて飛ばさない。** 手段があるのに使わず「確認できていません」と報告するのが、いちばん悪い。

確認の勘どころ:

- 画面を操作した直後に、同じ処理の中で `getComputedStyle` の結果を読むと、**変更前の値が返ることがある**。スクロールやクリックと、その結果の読み取りは**別々に実行する**
- スクリーンショットは、まだ描画が追いついていない瞬間を写すことがある。値で確かめられるものは、見た目だけで判断しない
- `:focus` のスタイルは、ブラウザのウィンドウにフォーカスが無いと評価されない。フォーカス時の見た目は、**CSS ルールが定義されているか**で確認する

#### 本当にブラウザを操作できないときだけ

- **ソースから確認できる範囲は自分で確認する**: CDN の URL とバージョン指定、`data-lucide` の名前、`aria-expanded` / `aria-controls` / `aria-label` の有無、画像 URL の到達性、`opacity: 0` の初期値が残っていないか、横幅を固定している箇所がないか
- **Artifact として表示し、見た目を確認してもらう**。そのうえで「プレビューで見えないもの」を伝える
- **自分で確認できなかった項目を、項目名を挙げて明示する**（「コンソールエラーと 404 は、この環境では確認できていません」）。確認したことにはしない

問題があればソースを修正し、再確認する。直せなかった点があれば、何がどう残っているかを明示してユーザーに伝える。
