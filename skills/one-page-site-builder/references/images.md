# 画像（Unsplash）

Unsplash から画像を検索し、Web ページ用に最適化した URL を使う手順。

## 画像の取得方法を決める

1. **Unsplash コネクタ（MCP）を使う。** ツール名は `search_photos` / `download_asset` など。API キーの用意やスクリプトの実行は不要で、コネクタがキーを持っている（プロジェクト側に独自のスクリプトや API キーが用意されていれば、そちらが優先）
2. コネクタが使えない場合は末尾の「コネクタが使えないとき」へ

**どちらの経路でも、ステップ 2〜4（情報の取り出し・URL の最適化・ダウンロードの記録）とクレジット表記は共通**。取得方法だけが変わる。

---

## ステップ 1: 画像を検索する

`search_photos` を呼ぶ。

- `query`: **短く絞ったキーワード 1 つ**。キーワードを並べても結果は良くならない
- 複数の異なる画像が必要なときは、**概念ごとに別々に呼ぶ**（「カフェの内装」と「コーヒーを淹れる手元」は別の検索）
- `orientation`: ヒーローや横長の帯には `landscape`
- `per_page`: 5〜10 程度

## ステップ 2: 結果から情報を取り出す

| フィールド | 用途 |
|---|---|
| `urls.raw` | 画像のベース URL（パラメータ付加前）。**これを使う** |
| `links.html` | Unsplash のページ URL（ユーザーに候補を見せるとき必須） |
| `id` | `download_asset` に渡す ID |
| `description` / `alt_description` | 画像選択の判断と `alt` 属性の下書きに使う |
| `user.name` | 撮影者名（クレジット表記用） |
| `user.username` | 撮影者の Unsplash ユーザー名（クレジットのリンク用） |

**画像選択の判断**: `description` / `alt_description` と検索順位を根拠に選ぶ。サムネイルの視覚確認は省略してよい。

## ステップ 3: 画像 URL を最適化する

`urls.raw` にパラメータを付加する。

| パラメータ | 推奨値 | 用途 |
|---|---|---|
| `w` | ヒーロー: 1920 / コンテンツ: 800〜1200 / サムネイル: 400 | 幅 |
| `q` | 80（重要な画像は 90） | 品質 |
| `fm` | webp | フォーマット |
| `fit` | crop | フィット |

`urls.raw` には既に `?ixid=...` が付いているので、**`&` でつなぐ**。

例: `https://images.unsplash.com/photo-xxx?ixid=...&w=1200&q=80&fm=webp&fit=crop`

**`urls.raw` のホットリンク以外は使わない。** Unsplash の API ガイドラインは「API 利用はすべて `photo.urls` が返すホットリンク URL を使わなければならない」と定めている。画像を自分のサーバーにダウンロードして再配信するのは規約違反になる。

## ステップ 4: ダウンロードを記録する（規約で必須）

画像をページに埋め込んだら、その画像の `id` を `asset_id` として **`download_asset` を呼ぶ**。

Unsplash のガイドラインは「ユーザーが画像を選んでブログ記事に使う、ヘッダーに設定する等、ダウンロードに相当する操作をしたとき」にこの記録を求めている。HTML への埋め込みはこれに該当する。

**この呼び出しは記録のためだけで、返ってくる URL は使わない。** `download_asset` は `fm=jpg` の URL を返すが、HTML に書くのはステップ 3 で `urls.raw` から組み立てた webp の URL のほう。返り値をそのまま `src` に入れない。

失敗しても処理は続行してよい。

## 使い方 A: ユーザーに候補を提示する

「探して」「どんな画像がある？」のように、ユーザーに選んでもらうのが目的のとき。

マークダウン表で提示する。各行に以下を含める:

- `links.html` へのクリッカブルリンク（ユーザーが画像を確認するために**必須**）
- 最適化済み URL（コピー用）
- 撮影者名

```
| # | 内容 | 撮影者 | 最適化URL |
|---|------|--------|-----------|
| [1](https://unsplash.com/photos/xxx) | 辞書のクローズアップ | Romain Vignes | `https://images.unsplash.com/photo-xxx?...&w=1920&q=80&fm=webp&fit=crop` |
```

ユーザーが画像を選んだ時点でステップ 4 を実行する。

## 使い方 B: HTML に埋め込む

ページ作成の一部として画像が必要なとき。候補提示は省略し、最適な画像を選んで直接組み込む。埋め込んだ時点でステップ 4 を実行する。

### 埋め込みの注意

**写真を敷く帯には、必ず写真の下にブランドカラーの濃い `background-color` を置く。**

```html
<section class="relative bg-primary-dark">
  <img src="https://images.unsplash.com/photo-xxx?...&w=1920&q=80&fm=webp&fit=crop"
       alt="" loading="lazy" decoding="async"
       class="absolute inset-0 w-full h-full object-cover opacity-60">
  <div class="relative">…白抜きの見出し…</div>
</section>
```

写真が表示されない環境（チャットの Artifact プレビューなど）でも、背景色があれば白抜き文字が読める。背景色がないと文字が消える。

`bg-primary-dark` は `@theme` に `--color-primary-dark` を定義してはじめて使える。Tailwind v4 は `--color-primary` だけから `bg-primary-900` のような濃淡を自動生成しないので、**存在しないクラス名を書くと背景色が付かず、この対策が無効になる**。

`alt` 属性は、装飾目的の背景写真なら `alt=""`、内容を伝える写真なら `alt_description` をもとに日本語で書く。

## クレジット表記

ガイドラインは、Unsplash・撮影者・撮影者のプロフィールへのリンクを表示することを求めている。フッターなどにまとめて置いてよい。

`utm_source` にはそのサイト・プロジェクトの名前を入れる。

```html
Photo by <a href="https://unsplash.com/@username?utm_source=サイト名&utm_medium=referral">撮影者名</a>
on <a href="https://unsplash.com?utm_source=サイト名&utm_medium=referral">Unsplash</a>
```

## フォールバック

1. **検索結果が的外れ・数が足りない**: 別のキーワードで再検索する（例: "coffee shop" → "cafe" → "coffee"）。概念ごとに分けて検索し直すのも有効
2. **コネクタが使えないとき**: Unsplash コネクタが接続されていない場合（ツールが見つからないか認証エラーになる）。プロジェクト側に用意された取得経路も無いなら、自分で別の経路を探さず、次のどちらかにする
   - 写真を使わない構成にする（ブランドカラーの背景、CSS グラデーション、Lucide アイコン、タイポグラフィ主体のヒーロー）。そのうえで「写真は後から差し替えられるようにしてあります」と伝える
   - ユーザーに画像の URL やファイルを提供してもらう

   どちらの場合も、**コネクタが接続されていないことをユーザーに伝える**（「Unsplash コネクタが使えないため、写真なしで作りました。接続すれば写真を入れられます」）。黙って写真なしで作らない
