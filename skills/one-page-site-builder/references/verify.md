# 生成後の確認

HTML を書いたら必ずここまで実施する。**ユーザーに「ブラウザで確認してください」と丸投げしない。**

## 確認する項目

1. コンソールエラーが 0 件
2. 画像と CDN がすべて読み込めている
3. デスクトップ幅・モバイル幅の両方でレイアウトが崩れていない（横スクロールが出ていない）
4. 固定ナビがスクロール前後で切り替わる
5. モバイルメニューが開閉し、`aria-expanded` が更新される
6. Lucide アイコンが描画されている
7. ブランドアイコン（SVG）が意図した色で見えている（黒のまま暗い背景に溶けていない）
8. アニメーション対象が「見えている状態」で止まっていない
9. フォームのバリデーションと送信が意図どおり動く

**「この環境では無理だろう」と決めつけて飛ばさない。** 手段があるのに使わず「確認できていません」と報告するのが、いちばん悪い。

---

## ステップ 1: サーバーを起動する

プロジェクト直下の `.claude/launch.json` に書く。HTML を作業ディレクトリの `index.html` に置いた場合はこのままでよい。

```json
{
  "version": "0.0.1",
  "configurations": [
    {
      "name": "onepage-static",
      "runtimeExecutable": "npx",
      "runtimeArgs": ["-y", "serve", ".", "-l", "4321", "--no-clipboard"],
      "port": 4321
    }
  ]
}
```

- `"serve"` の次の引数は **HTML が入っているフォルダ**（`public/index.html` なら `public`）
- **すでに `.claude/launch.json` がある場合は、`configurations` 配列に 1 件追加する。ファイルごと上書きしない**（プロジェクトの既存設定を壊す）
- Node が使えない環境なら Python でもよい:
  `"runtimeExecutable": "uv"`, `"runtimeArgs": ["run", "--no-project", "python", "-m", "http.server", "4321"]`

書いたら、その設定名でサーバーを起動し、ページを開く。`.claude/launch.json` を新しく作った場合は、作ったことをユーザーに報告する（勝手にファイルが増えたように見えるため）。

**ブラウザを操作できない場合だけ**、ステップ 2 を飛ばして末尾の「ブラウザが使えないとき」に従う。

## ステップ 2: 検証する

順番に意味がある。**上から順にやる。**

### 2-1. コンソールエラー（項目 1）

ページを開いた直後にエラーログを読む。0 件であることを確認する。

### 2-2. 画像がすべて読み込めているか（項目 2）

**一気に最下部へジャンプしてはいけない。** `loading="lazy"` の画像は通り過ぎただけでは読み込まれず、「読み込めていない」と誤判定する。

300〜500px 刻みでスクロールし、各ステップで少し待ってから、最後にまとめて判定する。

```js
document.documentElement.style.scrollBehavior = 'auto';  // smooth だと検証が安定しない
const h = document.body.scrollHeight;
for (let y = 0; y <= h; y += 400) {
  window.scrollTo(0, y);
  await new Promise(r => setTimeout(r, 200));
}
await new Promise(r => setTimeout(r, 2000));
[...document.images].map(i => i.naturalWidth);   // 0 が 1 つでもあれば読み込み失敗
```

`complete` では判定しない（未読み込みでも `false` になるため見落とす）。

### 2-3. アニメーションの取りこぼし（項目 8）

**ページを再読み込みしてから、一気に最下部へ飛ばす。** これが取りこぼしを出す唯一の操作。

```js
location.reload();
// 読み込み後
document.documentElement.style.scrollBehavior = 'auto';
window.scrollTo(0, document.body.scrollHeight);
await new Promise(r => setTimeout(r, 2000));
[...document.querySelectorAll('.reveal')].filter(e => getComputedStyle(e).opacity !== '1').length;  // 0 であること
```

0 でなければ、実装が IntersectionObserver 頼みになっている。SKILL.md「アニメーション（ライブラリを使わない）」のコードに差し替える。

### 2-4. 固定ナビの切り替え（項目 4）

スクロールさせる処理と、`getComputedStyle` を読む処理は**別々の呼び出しに分ける**。同じ処理の中で続けて読むと、変更前の値が返ることがある。

上端（`scrollY === 0`）とスクロール後で、背景（色・不透明度・ぼかし）とコントラストが変わっていること、**どちらの状態でも文字が読めること**を値で確認する。配色そのものは全体デザインに合わせた判断でよい。

### 2-5. モバイル幅（項目 3・5）

ビューポートをモバイル（375×812 など）に切り替えてから:

- メニューボタンをクリック → `aria-expanded` が `true` になり、`aria-label` が閉じる側の文言に変わり、パネルが開く
- アイコンが `menu` → `x` に変わっている（`#nav-toggle-icon` の `data-lucide` と `classList` を見る）
- もう一度クリック → すべて元に戻る
- `document.documentElement.scrollWidth === window.innerWidth`（横スクロールが出ていない）
- 2-2 と同じ要領でスクロールし、画像が読み込まれる

**終わったらビューポートをデスクトップに戻す。** 戻し忘れると、以降の確認もスクリーンショットもモバイル幅のままになる。

### 2-6. フォーム（項目 9）

`requestSubmit()` で送信を起こし、次を確認する。

- 未入力・不正なメール・短すぎる本文でエラーが表示される
- 正しい入力で成功メッセージが出る
- **`location.href` が変わっていない**（`preventDefault` が効いている）
- 送信先を用意していないなら `action` 属性が付いていない

### 2-7. 残りの項目（項目 6・7）

- Lucide アイコン: `document.querySelectorAll('i[data-lucide]').length === 0`（置き換わらず残っていたら名前が間違っている）
- ブランドアイコン: 各 SVG の `getComputedStyle(svg).color` が黒（`rgb(0, 0, 0)`）になっていないか。暗い背景に黒のまま置くと消える
- `:focus` の見た目は、ブラウザのウィンドウにフォーカスがないと評価されない。**CSS ルールが定義されているか**で確認し、「実際の描画までは確認していない」と報告する

## ハマりどころ

- **スクリーンショットは、まだ描画が追いついていない瞬間を写すことがある。** 画像が真っ黒・真っ茶色に見えても、`naturalWidth` が 0 でなければ読み込めている。**値で確かめられるものは、見た目だけで判断しない**
- **`html { scroll-behavior: smooth }` があるとスクロール検証が安定しない。** 検証中だけ `scrollBehavior = 'auto'` にする
- 操作（クリック・スクロール）と、その結果の読み取りは**別々に実行する**

## ステップ 3: ユーザーに渡す

1. **ブラウザのペインは開いたまま残す**。「このペインで実物が見られます」と伝える
2. サーバーを止めずに残すなら、そのこととポート番号も伝える
3. ファイルのパスを伝える
4. 自分で確認した項目と、確認できなかった項目を、項目名を挙げて報告する

問題があればソースを修正し、再確認する。直せなかった点があれば、何がどう残っているかを明示して伝える。

---

## ブラウザが使えないとき

ローカルサーバーを起動できない、またはブラウザを操作できない場合だけ:

- **ソースから確認できる範囲は自分で確認する**: CDN の URL とバージョン指定、`data-lucide` の名前、`aria-expanded` / `aria-controls` / `aria-label` の有無、画像 URL の到達性、`opacity: 0` が CSS だけの初期値になっていないか、横幅を固定している箇所がないか、`action` 属性の有無
- **自分で確認できなかった項目を、項目名を挙げて明示する**（「コンソールエラーと画像の読み込みは、この環境では確認できていません」）。確認したことにはしない
